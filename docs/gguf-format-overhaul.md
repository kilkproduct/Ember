# GGUF v2/v3 import, inspection and inference overhaul

## Actual app and root cause

The application remains Kotlin/Jetpack Compose (no WebView replacement). SAF
`ContentResolver` → bounded persistent private staging → Chaquopy/Python admission
→ native llama.cpp model/context/tokenizer/first-token check → atomic library
publication → Kotlin `LlamaInference`/JNI generation is the production path.
NumPy training/checkpoints/corpus/Parquet remain separate from foreign inference.

`ember/gguf_export.py::read_gguf_header` incorrectly required
`version == GGUF_VERSION`, where that constant is the **writer's** version 3.
The native engine already supported v2 LE. This was an Ember gate, like the
previous dense-only architecture gate, not evidence that GGUF v2 or Qwen3.5
needed a replacement inference engine.

Backend retained: checksum-pinned **llama.cpp b11838**, commit
`4231b23dc2c46661d01157aac5245bdcf03ce4b1`, MIT, source archive SHA256
`1395bfc5668ac43ff59dec7d4ee21e103ee6bb91ca8d10d704256ed8dd65e6b0`.
Its actual registry/factory drives admission; compiled capabilities are exposed
by C ABI, JNI/Kotlin and Python/RPC. Qwen3.5/3.5-MoE have full upstream graphs,
but no genuine Qwen3.5 weights or physical-device inference were available.

## Format support and boundaries

| Container | Metadata/tensor-table inspection | Native inference on Android |
|---|---|---|
| v2 little endian | tested | tested complete synthetic Llama graph |
| v3 little endian | tested | tested multiple complete synthetic graphs |
| v3 big endian | tested with independent official reader | **unsupported by pinned C++ reader on these little-endian ABIs**; explicitly rejected, never rewritten |
| v2 big endian | explicit unsupported variant | not supported |
| v1/future versions | explicit unsupported-version error | not supported/certified |

v2 and v3 both use 64-bit counts, string lengths, dimensions and relative data
offsets. v1 is not read using those widths. v3's opposite-endian version field
selects BE decoding for **all** numeric metadata, arrays and tensor descriptors,
not just the version. `GGUF` magic remains literal bytes. The writer also fixes a discovered non-default-alignment metadata-count bug, validates alignment/padding agreement, and emits typed empty arrays. Independent reference-reader tests check exact payloads and 32/128/8192-byte alignment. Export remains **v3 LE
only**; source imports and weight precision are never rewritten.

Parsing uses a read-only mmap of the file, not whole-model heap bytes. Before
constructing arrays/strings, counts are checked against file extent and aggregate
inspection budgets: 128 MiB decoded string bytes, 2 million decoded values,
100,000 metadata/tensor entries, nesting depth 4. These are explicit untrusted
metadata budgets, not weight-file size limits. The existing >64 MiB metadata
regression still passes. Limits can reject unusually huge metadata; this is not
misrepresented as an unsupported architecture or silently truncated metadata.

All scalar value types 0–12 and homogeneous/nested/empty arrays are decoded.
Keys/names, compiled dimension limits, signed-64-bit element overflow, GGML row
block divisibility, type layouts, UINT32 power-of-two alignment, data start,
absolute extent, overlaps, offsets and truncated payloads are checked. A sparse
file with a relative tensor offset **above 4 GiB** is inspected with <8 MiB
traced Python allocation. Unknown layouts remain explicit unsupported-tensor
states; recognizing a layout is never kernel/model readiness certification.

## Independent genuine-v2 regression

`tests/reference/gguf_v2_writer.py` is the **unmodified original upstream v2
writer**, commit `e394084166baac09e8ee9a08a4686f907f7e5291`, with its MIT license.
SHA256 `0f2d600e97b42a913520bc37576a42e9f5c5b5c0c9301f32e7453c0f61bccbd5`.
It independently serializes a complete deterministic synthetic Llama graph using
its original v2 layout. The file is checked against official `gguf==0.19.0`
`GGUFReader`, then loaded and generated by native llama.cpp. **No version bytes,
writer constants or source-file headers are patched.** This is a genuine v2
container regression, not a claim to have downloaded pretrained v2 weights.
Provenance/checksum: `verification/v2-fixture-provenance.json`.

## Broader executed compatibility

Host graph tests now additionally cover **Gemma, Phi-2, Command-R, DeepSeek's
leading-dense path and four-expert/top-2 Mixtral-style Llama MoE**, each F32 and
mixed Q8_0, with actual load/tokenizer/generation/unload. They complement existing
Llama, Qwen2/2.5/3, Mamba recurrent and Qwen3-MoE tests. These are full native
random graph fixtures, **not official pretrained family certification**, and
use deliberately documented fixture tokenizers. DeepSeek2/3 MLA, newer
Gemma/Phi variants, pretrained SentencePiece/tokenizer variants and real Mistral/
Mixtral performance remain unverified. See the per-architecture machine report
`verification/architecture-host.json` for source-only vs executed evidence.

Explicit host-only upstream quantizer fixtures then load and generate using:
**F16, BF16, Q4_0, Q4_1, Q5_0, Q5_1, Q8_0, Q2_K, Q3_K, Q4_K, Q5_K,
Q6_K, IQ4_NL, IQ4_XS, TQ1_0, TQ2_0, Q1_0, Q2_0**, with F32 baseline.
This tests real packed weights and actual CPU kernels, not header identifiers.
The host fixture quantizer is excluded from Android builds and never invoked
on import. Import still offers no automatic conversion/requantization.

The NVFP4 enum/layout exists, but this upstream CPU quantizer rejects its output
file type; that negative result is tested. **No NVFP4 inference certification is
made.** Q8_1, imatrix-only IQ and remaining compiled types without suitable real
fixtures are likewise not certified. Unknown types reject explicitly; known
but unavailable kernels/operations are decided by upstream load/context/decode
with original errors retained.

## Inspector and readiness

Import shows the native Compose metadata inspector before native validation, including for files which cannot be registered. Chat → Model library → **Details** reopens it for registered files. RPC
`model.inspect` reads metadata without loading the weights or requiring an
architecture allowlist: name, architecture, version/endian, bytes, stored tensor
elements (not invented active/tied parameter counts), declared geometry/context,
vocabulary/tokenizer, tensor format counts, modalities, CPU backend pin and
compatibility limitations. Missing values remain missing. The inspector clearly
states that declared metadata is not inference proof. Invalid files, unknown
layouts, unsupported architectures/interfaces, big endian and multipart files
receive distinct states. No gigantic vocabulary/template dump is sent to UI.

Actual import must still pass structural inspection, unchanged upstream graph
loading/context/tokenizer, and first-token generation using the **same private
inode/handle** before publication/selection. Failures/cancellation clean only
owned temporary files and preserve models, training and datasets. Applied
context/precision are not silently lowered. CPU mmap, admission checks,
background workers, unload and lock-free native cancellation remain in place.

The backend can load conventionally named adjacent split GGUF sets, but Android's
single-document private-staging UI does **not** assemble those sets. Split-count
metadata is detected before graph load/publication, with a missing-shard/
unsupported-arrangement message rather than trying to open a UUID as a shard
prefix. Use a complete single-file GGUF. No blind SAF URI/path reopen, source
renaming, shard merging or deletion is performed. Multi-document shard import
remains a limitation, not a claimed feature.

Text only: upstream tokenizers/samplers/EOG handling are retained. Model templates
use upstream's built-in formatter; unsupported templates reject before import
registration. No arbitrary Jinja execution, vision preprocessing, projectors,
audio or video input path is claimed. Absence of a template uses ordinary raw
text with model BOS policy. Pretrained inference does not make GGUFs trainable;
strict EMB4-to-Llama export is unchanged.

## Tests and build evidence

**267 Python tests pass** locally, with two existing divergence-test overflow
warnings. Includes independent v2/v3/BE parsing, scalar/array types, future magic/
versions, truncated/bomb metadata, invalid dimensions/types/offsets/alignment,
64-bit sparse-file inspection, shard diagnosis, real v2 generation, added graph
families/quantizations, and existing training/EMB4/Parquet/SAF/lifecycle suites.
Machine-readable test cases: `verification/gguf-overhaul-junit.xml`.

Reproduce after fetching the pinned source:

```sh
cmake -S native/llama -B native/build-llama -DCMAKE_BUILD_TYPE=Release -DEMBER_BUILD_LLAMA_TESTS=ON
cmake --build native/build-llama -j2
export EMBER_LLAMA_LIB="$PWD/native/build-llama/libember_llama.so"
OPENBLAS_NUM_THREADS=1 pytest -q tests/ --junitxml=/tmp/gguf-overhaul.xml
```

Android CI builds only the universal development-signed APK (arm64-v8a/x86_64),
JVM tests and signature/package checks. No GPU/accelerator, physical installation,
original user-file acceptance, genuine Qwen3.5 or real SAF device result is
asserted. Historical SAF emulator grant-harness failure remains unresolved;
its instrumentation would require another test APK, excluded under the standing
universal-only APK requirement. Final CI/artifact evidence must refer to the
new delivery run, not a historical build linked by older documents.
